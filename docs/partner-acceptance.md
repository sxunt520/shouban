# R1M 共同验收流程

自动入口：`npm run accept:partner`。交付入口：`npm run export:partner`。先按 [模拟器说明](../apps/device-simulator/README.md) 配置 Node / MySQL；具体协议见 [合作方对接入口](partner-handoff.md)。

## 自动契约验收

验收先进行 APP/API 类型检查、API 编译，再串行执行 R1M、旧 MQTT、参考语音测试。每组有三分钟超时；测试使用真实 MySQL、MQTT Broker、WS 与 UDP，语音提供商使用替身。失败仍输出报告并返回非零状态；API 编译失败则跳过后续测试，避免用旧产物伪造通过。测试计数包含 Node 父级测试。

报告列出每组及每个用例结果，并单独列真实硬件未验收项。源码在运行前后计算指纹；运行期间变化会使汇总失败，验收后源码变化会阻止导出。日志在本地，不进入交付包。

| 自动场景 | 合格条件 |
| --- | --- |
| OTA / 激活 / 认领 | 身份、HMAC、challenge 时效、一次性票据、账号认领和角色选择均正确 |
| WS v1 | 裸 Opus 往返，头/版本/会话鉴权，旧语音轮次失效 |
| MQTT + UDP | 独立 codec 与固定向量一致；音频往返、丢帧失败、包去重、方向隔离 |
| 在线与重连 | Broker 证据与语音会话分开，断连和重订阅符合状态逻辑 |
| 音量 / 定位 | custom 与 HTTP 共用账本，重复指令不重复执行，回执不能跨设备 |
| 主动播报 / 停止 | 只有有效完成回执成功；生成中/发送中停止，迟到结果不复活 |
| 提醒 | 同一次调度不重复创建，离线/过时/忙碌不补播，编辑暂停删除只取消关联任务 |
| NFC | 账号隔离、匹配切换、未知标签、取下保留角色、去重、旧序号/会话拒绝 |
| 兼容回归 | 旧 MQTT、HTTP 与参考语音路径正常 |

## 手机与真实 R1M 验收

每次填写机型、固件版本、APP 版本/平台、后台版本、契约版本、WS/MQTT、Wi-Fi/4G、北京时间起止、实际结果和证据。各项初始为“待测”，不得用自动测试结果代替。真实提供商和扬声器测试请准备测试文本或经授权的音频。

| 编号 | 操作 | 预期与证据 | 初始状态 |
| --- | --- | --- | --- |
| H01 | 长按进入配网，APP 扫描并连接 | ZAOC_ 可发现，确认 FF00，FF01/FF03 通知成功开启 | 待测 |
| H02 | 错误密码，再原连接提交正确密码 | 失败 status=0 可重试；成功 status=1 后重启，APP 不误报 | 待测 |
| H03 | 中文 SSID / 分包 / 空密码 / 中途断开 | UTF-8 正确；按 MTU 分包；失败不认领，重试可恢复 | 待测 |
| H04 | Wi-Fi 配网后激活与认领 | OTA 与云端可达后才绑定；账号、MAC 与角色正确 | 待测 |
| H05 | 真实 4G，跳过 BLE 直接认领 | 蜂窝网络连接，OTA 选择 MQTT；不是电脑模拟网络 | 待测 |
| H06 | 两台设备分别调音量与定位 | 实际音量/灯效正确，commandId 回执不串设备 | 待测 |
| H07 | 麦克风说话，经云端回复 | ASR 文本、角色回答、音色与扬声器声音正确，无丢帧误完成 | 待测 |
| H08 | APP 主动播报并中途停止 | 真正播完才 finished；停止后扬声器停止并上报 stopped | 待测 |
| H09 | 播报中开始录音 / 切换角色 | 旧音频及时停止，旧回复不晚到，后续声音属于新角色 | 待测 |
| H10 | 一次性提醒、每日提醒、暂停删除 | 到点仅播放一次；暂停取消对应播放，停止无关任务不受影响 | 待测 |
| H11 | 到点离线，恢复连接 | 显示未执行原因；不突然补播积压提醒 | 待测 |
| H12 | 已绑/未知标签、取下、快速换卡 | 真读卡 UID 与匹配正确；旧标签移除不清新标签，角色与取消策略正确 | 待测 |
| H13 | 断网、Broker/API 重启、设备重启 | 自动重新 OTA/hello，旧 session/key 不复用；状态证据正确 | 待测 |
| H14 | 真实 4G 弱网、NAT 变化、Wi-Fi/4G 切换 | 新会话/探测恢复 UDP，无旧音频重播或错误成功 | 待测 |
| H15 | 解绑后新账号认领 | 旧账号不可控制，旧指令与提醒失效，NFC 映射按新账号匹配 | 待测 |
| H16 | iOS 授权、扫描、配网及业务页面 | CoreBluetooth 通知与生命周期正确，界面/接口流程可用 | 待测 |

部署验收另外检查正式 Broker、TLS/证书、出厂验证、凭证轮换与持久化、多实例会话路由、固件 OTA 签名等。当前只交付本地参考，不提供已经通过的生产验收结论。

建议记录每个失败场景的最后一条有效消息和第一条异常消息；脱敏 token、设备密钥、Wi-Fi 密码和个人音频，保留 eventId/commandId、时间、状态及错误原因。

## 报告和交付

`.data/partner-acceptance/latest.json` 指向最近报告；`report.json` 供程序读取，`report.md` 供双方评审。失败查对应本地 `.log`。异常退出遗留 `running.lock` 时，先核对其中 PID 已停止，再删除锁重试。

执行 `npm run export:partner` 会验证源码指纹与通过报告，生成 `.data/partner-delivery/<UTC时间>/shouban-r1m-reference.tar.gz`、SHA-256 文件和含逐文件哈希的清单。包含参考 APP/API/模拟器源码和测试，不含 `.env`、运行凭证、音频、构建产物或旧参考固件。接收方在自己的环境重新验收，并按本表补真实设备结果。
